CLOUDFLARE R2 SETUP FOR OTDR TOOL
=================================

1. Create a private R2 bucket
-----------------------------
- Recommended name: otdr-tool-private
- Storage class: Standard (the R2 free tier applies to Standard).
- Do not enable public access or an r2.dev public URL.

2. Create a bucket-scoped API token
-----------------------------------
- Permission: Object Read & Write.
- Scope the token to only the OTDR bucket.
- Record the Account ID, Access Key ID and Secret Access Key once.
- Never put these values in frontend code or a REACT_APP_* variable.

3. Configure these four server-side environment variables
---------------------------------------------------------
R2_ACCOUNT_ID=<32-character Cloudflare account id>
R2_BUCKET_NAME=otdr-tool-private
R2_ACCESS_KEY_ID=<bucket-scoped access key id>
R2_SECRET_ACCESS_KEY=<bucket-scoped secret access key>

Set all four in Vercel Project Settings > Environment Variables for every
environment that must work (Production and, if used, Preview/Development).
The .env.example file is a checklist only; this backend intentionally does not
load .env files automatically. For local development, set the four variables
in the same terminal that starts uvicorn (see section 6). Never commit values.

4. Configure bucket CORS
------------------------
Replace the production origin below if the actual Vercel/custom domain is
different. Origins must match exactly and must not have a trailing slash.

[
  {
    "AllowedOrigins": [
      "https://otdr-tool.vercel.app",
      "http://localhost:3000"
    ],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type", "Content-Length", "If-None-Match"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]

The ETag exposure is required to complete multipart uploads. Do not replace
the exact origins with "*" on a production bucket.

5. Configure lifecycle safety rules
-----------------------------------
- Prefix otdr/input/: expire objects after 1 day.
- Prefix otdr/input/: abort incomplete multipart uploads after 1 day.
- Do not add automatic expiry to otdr/output/ until the required report
  retention period has been explicitly agreed.

Successful conversions still delete their input objects immediately. The
lifecycle rules only clean abandoned/failed uploads.

6. Local verification
---------------------
Use Python 3.12 or newer. Python 3.9 is no longer supported by current boto3.

In PowerShell, set credentials only in the current terminal:
  $env:R2_ACCOUNT_ID="..."
  $env:R2_BUCKET_NAME="otdr-tool-private"
  $env:R2_ACCESS_KEY_ID="..."
  $env:R2_SECRET_ACCESS_KEY="..."

Install and start the backend:
  py -3.13 -m pip install -r backend/requirements.txt
  py -3.13 -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

Frontend (a second terminal):
  npm.cmd --prefix frontend start

Open:
  http://localhost:3000

Required smoke test sequence:
1) one small .sor file;
2) mixed .sor + unsupported file (only .sor is processed);
3) a file over 100 MiB to exercise multipart;
4) full report generation and automatic signed download;
5) confirm input objects are deleted after success;
6) confirm a failed multipart is removed by abort/lifecycle.

The repository tests use mocks and cannot prove real bucket CORS or credentials.
Do not call the migration complete until all six live smoke checks pass.

7. Production safety checks
---------------------------
- The server signs each exact pathname and size into a one-hour upload session;
  multipart part URLs are created just in time and remain valid for 15 minutes.
- The app is still intentionally usable without user login. Protect the public
  session endpoint with the deployment platform's rate limiting/access control
  if untrusted Internet users can reach it; repeated valid sessions can still
  consume R2 operations and storage.
- Confirm Vercel Fluid compute is enabled. The report request has a 180-second
  client timeout and needs a function limit above 180 seconds.
- Monitor otdr/output/ storage. Outputs are not expired automatically because a
  retention period has not been approved; set an alert before the free allowance
  is exhausted, then agree a retention policy before adding an output lifecycle.
- Before Vercel CLI deployment, run `vercel link` and confirm the linked project
  is `otdr-tool`; the existing local .vercel link may point to another project.
